Chapter 01 · Prep work

Get your tools sharpened.

You'll need three accounts and one tool installed. If you already did this for Sourdough Database, skim it and skip to chapter 2 — you're good.

A GitHub account

This is where your code lives. Free forever for public repos. Sign up at github.com/signup. Pick a username you don't mind being public — mine is recommended to be something like kylewebear.

A Netlify account

This is what makes your site visible on the internet. Free tier is more than enough. Sign up at app.netlify.com/signup — and choose "Sign up with GitHub" when offered. It saves time later.

Git installed on your Mac

Open Terminal (⌘ + Space, type "Terminal", hit return). Paste this and press return:

check git
$ git --version git version 2.43.0 # your number may differ — that's fine

If it prints a version, you're done. If it says "command not found" or pops up a dialog asking to install developer tools, click Install and wait a few minutes. When it finishes, run git --version again.

A code editor (optional but helpful)

VS Code is free and the safest pick if you don't already have one. You don't strictly need it — you can edit HTML in TextEdit if you're feeling rugged — but it'll save you headaches.

Tip · git config (one-time)

Tell git who you are so your commits aren't anonymous. Run these once, ever, on this machine:

git identity
$ git config --global user.name "Kyle Weber" $ git config --global user.email "your@email.com"

Use the same email you'll use for GitHub.

Chapter 02 · Files

Get the files into one folder.

Before git, just pile your stuff up neatly.

Make a project folder

I recommend somewhere visible like your Desktop or Documents. Call it something obvious — kylewebear-com works.

Move the right files in

Drag the four files I gave you into that folder, then rename them so the file system knows what's what:

  • kylewebear-index.html → rename to index.html
  • kylewebear-og-image.png → rename to og-image.png
  • kylewebear-favicon.svg → rename to favicon.svg

Your folder should now look like this:

kylewebear-com/
kylewebear-com/ ├── index.html ├── og-image.png └── favicon.svg
Important · the filename matters

The HTML file must be named exactly index.html. That's the file Netlify (and every web host) looks for when someone visits your domain. Capitalization counts: Index.html and INDEX.HTML are different files as far as the web is concerned.

Sanity check — open it in a browser

Double-click index.html. It should open in your default browser at a file:// address and look exactly like the version I showed you. The OG image and favicon don't render at file:// URLs the way they do online, so don't worry if those look off — they'll work once deployed.

Chapter 03 · Local git

Tell git what to track.

Git is a time machine for your folder. You take "snapshots" (called commits) so you can roll back if you wreck something. Here's how to start.

Open the folder in Terminal

The fastest trick on Mac: in Finder, right-click your kylewebear-com folder and choose "New Terminal at Folder". Terminal opens already inside the folder.

If that's not enabled, open Terminal manually and use cd to navigate:

navigate
$ cd ~/Desktop/kylewebear-com # adjust path if it's elsewhere $ ls favicon.svg index.html og-image.png

The ls command lists the folder contents. If you see your three files, you're in the right place.

Initialize git

This creates a hidden .git folder that does the actual time-machining. You only do this once per project.

init repo
$ git init -b main Initialized empty Git repository in /Users/kyle/Desktop/kylewebear-com/.git/

The -b main bit tells git to call the default branch main instead of the older master. GitHub uses main, so it's smoother to start there.

Stage and commit your files

Two steps: add tells git "track these," commit takes the snapshot.

first commit
$ git add . $ git commit -m "Initial commit — bear is online" [main (root-commit) a1b2c3d] Initial commit — bear is online 3 files changed, 1500 insertions(+)

The . in git add . means "everything in this folder." The -m flag attaches a message describing what you did — keep these short and meaningful, future you will thank present you.

Tip · checking what git sees

Anytime you want to know what git is tracking or what's changed, run git status. This is your most-used command. Run it often.

Chapter 04 · GitHub

Send it up the mountain.

Right now your code only exists on your laptop. Now you'll push it to GitHub so the internet (and Netlify) can see it.

Create a new repo on GitHub

Go to github.com/new. Fill it out like this:

  • Repository name: kylewebear-com (or whatever — it doesn't have to match your folder name, but it's nice when it does)
  • Description: "My personal website" (optional)
  • Public — keep this. Public repos are free forever and there's nothing sensitive in here.
  • Do NOT check "Add a README" or "Add .gitignore" or "Choose a license." Adding any of these creates a commit on GitHub that conflicts with your local repo. Leave them all unchecked.

Click "Create repository". GitHub will show you a page with setup instructions — ignore them, the right ones are below.

Connect your local repo to GitHub

On that GitHub page, copy the URL ending in .git (it looks like https://github.com/kylewebear/kylewebear-com.git). Then back in Terminal:

link remote
$ git remote add origin https://github.com/YOUR-USERNAME/kylewebear-com.git

Replace YOUR-USERNAME and the repo name with whatever yours are. origin is git's default nickname for "the main remote copy" — you'll see it everywhere.

Push your code up

push
$ git push -u origin main Enumerating objects: 5, done. Counting objects: 100% (5/5), done. Writing objects: 100% (5/5), 285.21 KiB | 8.00 MiB/s, done. Total 5 (delta 0), reused 0 (delta 0) To https://github.com/kylewebear/kylewebear-com.git * [new branch] main -> main branch 'main' set up to track 'origin/main'.

The -u flag links your local main branch to the remote one, so future pushes are just git push with no arguments.

Authentication · the password thing

GitHub doesn't accept your account password for git pushes anymore. The first time you push, macOS will pop up an authentication dialog — pick "Sign in with your browser" and follow the prompts. After that, your Mac's keychain remembers and you won't have to do it again.

If no dialog appears and Terminal prompts you for a password, see the troubleshooting section — you'll need a Personal Access Token.

Verify it landed

Refresh the GitHub repo page in your browser. You should see your three files. If you do, that part's done — your code is on GitHub.

Chapter 05 · Netlify

Plug GitHub into Netlify.

This is the magic part. Once connected, every push to GitHub auto-deploys to your live site within a minute or two.

Start a new site

Sign in at app.netlify.com. On the dashboard, click "Add new site" → "Import an existing project."

Choose GitHub as the source

Click "Deploy with GitHub." Authorize Netlify to access your repos when asked. You can either grant access to all your repos, or just specific ones — picking only this one is the more cautious choice if you'd prefer.

Pick the repo

Find kylewebear-com in the list and click it.

Confirm build settings

Netlify will show you a settings screen. Since this is just plain HTML, leave everything blank or default:

  • Branch to deploy: main (should be auto-filled)
  • Build command: leave empty
  • Publish directory: leave empty (or put . if it complains)

Click "Deploy site."

Wait ~30 seconds

Netlify will build (which for an HTML-only site means just copying files) and assign you a random URL like curious-bear-a1b2c3.netlify.app. Click it. Your site is live.

Tip · rename the Netlify subdomain

Auto-generated names are random. To clean it up: in Netlify, go to Site configuration → Site details → Change site name. Pick something like kylewebear and your URL becomes kylewebear.netlify.app. Useful even if you're going to use a custom domain — it's a clean fallback URL.

Chapter 06 · Updates

The three-line ritual.

Once everything's wired up, updating the site is just three commands. Memorize this rhythm.

You edit a file. You save. Then in Terminal, from inside your project folder:

the three-line ritual
$ git add . $ git commit -m "Updated cocktail descriptions" $ git push

Within ~30 seconds, Netlify picks up the push and redeploys. You can watch it happen in real time on the Netlify dashboard under "Deploys."

Tip · good commit messages

Future-you reading "stuff" or "fix" in six months will hate present-you. Write in the imperative — "Add fern illustration," "Fix nav spacing on mobile," "Update OG image." It takes 2 extra seconds and saves real frustration when you need to find when something changed.

If you mess something up

Git keeps every snapshot. To see them: git log --oneline. To roll the working folder back to a specific snapshot temporarily: git checkout COMMIT-HASH . (note the trailing dot). To undo and return to latest: git checkout main -- .

If everything's truly on fire, you can re-deploy any past version directly from Netlify's "Deploys" tab — find a working deploy and click "Publish deploy." No git needed.

Reference · Troubleshooting

Problems you'll probably hit.

Tap any one to expand. These are the snags that catch most people the first time around.

"git: command not found"

Git isn't installed. Run xcode-select --install in Terminal — a dialog will pop up. Click "Install" and wait. When it finishes, try git --version again.

If xcode-select is also missing, install Homebrew first (brew.sh) and then brew install git.

"fatal: not a git repository"

You're running a git command in the wrong folder. Run pwd to see where you are, then cd into your project folder. Or you forgot to run git init first.

"Permission denied" or password prompt won't accept your password

GitHub stopped accepting account passwords for git operations in 2021. You need either browser-based auth (the dialog from earlier) or a Personal Access Token.

To create a token: GitHub → Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token. Give it the repo scope, copy the token (you'll only see it once), and paste it as your password the next time git asks.

Better long-term: install GitHub CLI with brew install gh, then gh auth login handles all auth automatically.

"failed to push some refs" / "rejected — non-fast-forward"

Usually means you accidentally added a README or other file on GitHub when creating the repo, so GitHub has commits your local copy doesn't. Run git pull origin main --rebase to merge them in, then git push again.

If that gets weird, the easiest fix for a brand-new repo is to delete it on GitHub and recreate it without any starter files, then push fresh.

Netlify shows "Page not found"

Most common cause: your HTML file isn't named index.html exactly (case-sensitive), or it's inside a subfolder. Netlify only serves index.html at the root.

Check on GitHub that the file shows as index.html at the top level of the repo. If it's wrong locally, rename it: git mv Index.html index.html, then commit and push.

OG image / social preview isn't showing up when I share the link

First, make sure og-image.png is at the root of your repo (not in a subfolder), and that your index.html references it correctly in the meta tags.

Then test with a debugger:

  • opengraph.xyz — universal preview
  • Twitter Card Validator — for X/Twitter
  • LinkedIn Post Inspector — refreshes LinkedIn's cache

Important: services like Twitter/iMessage cache previews aggressively. If you update your OG image after sharing the link once, the cached version may stick around for hours/days. The validators force a fresh fetch.

I edited a file but Netlify isn't redeploying

Did you actually push? Editing locally doesn't deploy anything. Run git status — if it lists changed files in red, you haven't committed. Run the three-line ritual.

If you committed but didn't push, run git push. Check Netlify's "Deploys" tab to see whether a deploy started after the push.

"untracked working tree files would be overwritten by checkout"

You've got files in the folder that git doesn't know about, and a git command wants to remove or replace them. Either commit them, or move them out of the folder, or use git stash to set them aside temporarily.

I committed something I didn't mean to (a password, a giant file, etc.)

If you haven't pushed yet: git reset HEAD~1 undoes your last commit but keeps the file changes.

If you already pushed and it's a secret/password — assume the world has seen it. Rotate that password/key immediately. Then for actually removing it from history, see GitHub's official guide. It's involved but doable.

Reference · Cheat sheet

Terminal commands, laminated.

Every command you'll actually use on a regular basis. Bookmark this page; this section alone is worth more than the rest combined once you're past setup.

The Three-Line Ritual (90% of your usage)

git add . Stage every change in the current folder.
git commit -m "message" Take a snapshot with a description of what changed.
git push Send your commits up to GitHub. Netlify deploys automatically.

Checking what's going on

git status Show what's changed but not yet committed. Run this constantly.
git log --oneline List your commit history, one line each. Press q to exit.
git diff Show exactly what's changed in your files since the last commit.
git remote -v Show where "origin" points to (i.e. which GitHub repo you're connected to).

Navigating the file system

pwd "Print working directory" — show which folder you're currently in.
ls List files in current folder.
ls -la List ALL files including hidden ones (like .git) with details.
cd folder-name Change into a subfolder.
cd .. Go up one folder.
cd ~ Go to your home folder.
open . Open the current folder in Finder. Works on macOS only.

Recovery / Undo

git restore filename Discard unsaved changes to a file (revert it to last commit).
git restore . Discard ALL unsaved changes. Use with caution.
git reset HEAD~1 Undo last commit, keep the changes (so you can re-commit differently).
git stash Set aside changes temporarily to come back to later.
git stash pop Bring stashed changes back.

One-time setup

git init -b main Start tracking a new project. Run once per project.
git remote add origin URL Connect local repo to GitHub repo. Run once per project.
git push -u origin main First push — sets up tracking. After this, just git push.
git config --global user.name "..." Set your git username. Run once ever, on this machine.
git config --global user.email "..." Set your git email. Run once ever, on this machine.

Terminal lifesavers

↑ (up arrow) Recall the last command you ran. Keep tapping for older ones.
Tab Auto-complete the file or folder name you're typing.
Ctrl + C Cancel whatever is currently running.
Ctrl + L Clear the terminal screen. Same as typing clear.
clear Clear the screen. Cleaner workspace, same scrollback.
history Show all the commands you've ever run.
